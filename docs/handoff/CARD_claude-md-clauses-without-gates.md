# CARD · §claude-md-clauses-without-gates — 조항은 있는데 아무 게이트도 안 보는 것

- 상태: 🔴 미판정 (전수 0)
- 발단: 2026-08-26 · footer 조항 위반 발견 (호영님 판정 → commit-msg 훅 신설)
- 선행: `.husky/commit-msg` (§commit-footer-gate)

## 발단이 된 사례

`CLAUDE.md` "Commit Convention" 의 마지막 줄:

```
footer: 없음 (Anthropic Co-Authored-By 사용 금지 — 호영님 통제 구조)
```

조항은 `e1cb184f`(2026-05-26)에 들어왔고 그 뒤 200커밋은 위반 0 이었다.
그런데 2026-08-20 부터 갑자기 붙기 시작했다.

```
최근  30 커밋   20 / 30 위반
최근 100 커밋   52 / 100 위반
최근 300 커밋   52 / 300      ← 101~300 구간은 0 / 200
가장 오래된 위반  2026-08-20  fix(csrf): 랩 운영 계열 6건 raw fetch → csrfFetch
```

⚠️ **창을 하나만 재면 결론이 뒤집힌다.** 전체 이력에서 세면 2,166건이 나오는데
그건 조항 도입 **이전**까지 포함한 수라 "오래된 관행" 처럼 보인다. 최근 100만
재면 52/100 이라 "절반이 위반" 으로 보인다. 두 창(0~100, 101~300)을 나란히
놓아야 "6일 전에 시작됐다" 가 나온다. 계수는 창을 최소 두 개 잡는다.

## 왜 카드인가

sentinel 40건 · pre-commit · pre-push · tsc 27 — **어느 것도 커밋 메시지 형식을
보지 않는다.** 게이트가 안 보는 조항은 6일이면 조용히 무너졌다.

🔑 오늘 세션의 축이 하나 더 늘었다.

```
소스는 봤고 화면은 안 봤다     sentinel 은 소스를 읽고, 결함은 렌더된 화면에 있었다
조항은 있었고 아무도 안 읽었다  게이트가 안 보는 조항은 문서일 뿐이다
```

`CLAUDE.md` 에는 다른 조항도 많다. 그중 **게이트가 강제하는 것과 안 하는 것이
갈라져 있고**, 안 하는 쪽이 몇 개인지 아직 세지 않았다.

## 판정 방법 (이 카드의 본체)

조항 하나하나에 대해 **그것을 강제하는 게이트를 지목**한다.
"지킬 것 같다" 가 아니라 **어느 파일의 어느 검사가 그것을 본다**를 적는다
(§reachability — 조항의 존재를 본 도구와 강제를 확인하는 도구가 달라야 한다).

### 절차

1. `CLAUDE.md` 를 조항 단위로 쪼갠다. 산문 설명이 아니라 **판정 가능한 진술**만
   센다("~하지 말 것", "~는 canonical 이다", "~형식을 쓴다").
2. 조항마다 다음 셋 중 하나로 분류한다.

   | 분류 | 뜻 | 처리 |
   | :--- | :--- | :--- |
   | 게이트 있음 | 지목 가능한 검사가 있다 (sentinel 파일명·훅·CI step) | 지목만 적고 통과 |
   | 게이트 없음·계수 가능 | 기계로 셀 수 있는데 아무도 안 센다 | **게이트 후보** |
   | 게이트 없음·판단 필요 | 사람 판단이 필요해 기계화가 어렵다 | 미판정으로 남긴다 |

3. **계수 가능 여부가 갈림길이다.** footer 조항은 `grep` 한 줄이라 훅을 붙였다.
   "canonical truth 를 UI state 가 대신 들지 않는다" 같은 조항은 그렇지 않다.
   기계화가 어려운 것을 억지로 게이트화하면 오탐이 규율을 갉는다.
4. 실측으로 **현재 위반 수**를 센다. 창을 최소 두 개 잡는다(최근 N · 그 앞 N).
   위반 0이면 게이트가 없어도 당장은 무해하다 — 그 사실을 적는다.

### 결과 처리

- 게이트 후보만 훅/sentinel 로 옮긴다. 조항 전체를 한 번에 게이트화하지 않는다.
- 기계화 못 하는 조항은 **미판정으로 남긴다.** "지켜지고 있을 것" 으로 세면
  footer 조항과 같은 일이 또 생긴다.
- 조항이 실물과 다르면 조항을 고칠지 실물을 고칠지 호영님 판정을 받는다.
  둘 중 하나로 land 하지 않으면 다음 세션이 같은 계수를 다시 세게 된다.

## 이미 처리한 것

```
footer (Co-Authored-By 금지)   .husky/commit-msg 신설 (2026-08-26)
                               이력 52건은 재작성하지 않는다 (푸시된 이력 재작성이 더 나쁜 거래)
                               이 훅은 앞으로만 막는다
```

### ⚠️ 첫 판이 오탐을 냈다 — 게이트가 자기 커밋 메시지를 거부했다

첫 구현은 `grep -qi 'Co-Authored-By'` 로 **문자열**을 막았다. 그런데 이 훅을
도입하는 커밋의 본문에 조항을 설명하는 산문이 있었고, 거기 그 이름이 들어간다.
게이트가 자기 자신을 막았다.

🔑 **잠그는 결정은 "트레일러가 없다" 이지 "그 이름이 안 나온다" 가 아니다.**
   git 트레일러는 줄 맨 앞 + 콜론이므로 그 형태만 막는다:
   `grep -qiE '^Co-Authored-By[[:space:]]*:'`

이건 오늘 세운 4번 경로(부정 단언에 값을 박았다)의 **거울상**이다.
부정 단언이 너무 좁으면 침묵하고, 너무 넓으면 오탐한다. 둘 다 원인은 같다 —
**결정이 아니라 표면을 잠갔다.** 넓게 틀리면 시끄러워서 바로 잡히고, 좁게
틀리면 조용해서 6일을 산다. 그래서 넓은 쪽 실수가 덜 나쁘지만, 옳은 것은
결정을 잠그는 것이다.

검출력 실증 (git 이 실제로 타는 `.husky/_/commit-msg` 경로로 · 5/5):

```
정상 커밋                              exit 0  통과
Co-Authored-By: … 트레일러             exit 1  거부
co-authored-by: … 소문자 트레일러       exit 1  거부
조항을 논하는 산문 (이름만 등장)         exit 0  통과   ← 첫 판이 여기서 오탐
주석(#) 안에만 있음                     exit 0  통과
```

⚠️ 훅을 만들 때 **git 이 실제로 타는 경로**로 실증해야 한다. `core.hooksPath` 가
`.husky/_` 라 `.husky/commit-msg` 를 직접 실행하는 것은 디스패처를 건너뛴다.
그리고 `chmod +x` 후 `git ls-files -s` 로 모드가 100755 인지 본다 — 파일시스템
권한과 git 이 기록한 모드가 다를 수 있다(이번에 100644 로 들어갔다).
