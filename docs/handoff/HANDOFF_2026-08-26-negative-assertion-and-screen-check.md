## 1. §reachability-needs-a-different-tool (한 줄 추가 · 여섯 줄 → 일곱 줄)

존재를 확인한 도구와 도달을 확인하는 도구가 매번 달랐다.

| 대상 | 존재를 본 도구 | 안 센 것 |
| :--- | :--- | :--- |
| 파일 | `ls` 로 봤다 | importer 를 안 셌다 |
| 분기 | 코드를 읽었다 | 조건이 참이 되는 경우를 안 셌다 |
| 컬럼 | 스키마를 봤다 | 생산자를 안 셌다 |
| 집계 | 값을 봤다 | 소비자를 안 셌다 |
| 추적 | 파일이 있었다 | `git ls-files` 를 안 했다 |
| 쿼리 | `include` 를 봤다 | 그 쿼리가 무엇을 반환하는지 안 셌다 (select 부재 = 전부 반환) |
| **생성물** | **`git ls-files` 로 추적을 봤다** | **빌드 스크립트가 덮어쓰는지를 안 셌다** |

일곱 번째 줄이 오늘 나왔다. `migration-manifest.json` 이 git 추적된다는 것을 확인하고
"커밋된 상수라 배포 확인에 못 쓴다" 고 판정했는데, `package.json` 의 `prebuild` 가
매 빌드마다 그 파일을 재생성하고 있었다. **추적됨 ≠ 커밋값이 배포됨.**

착수 시: 존재를 확인한 도구를 적고, 도달을 확인할 **다른** 도구를 지정한다.
생성물이면 `prebuild` / `postinstall` / 빌드 스크립트를 먼저 읽는다.

## 2. §verification-loss (네 번째 경로 추가 — 가장 나쁘다)

| # | 형태 | 예 | 소리 |
| :-- | :--- | :--- | :--- |
| 1 | 행위도 결과도 안 봤다 | 스테이징 잔여 → `git commit --only` | 침묵 |
| 2 | 행위를 봤다 | 의도적 은퇴 → git 층 + sentinel 층 잠금 | 침묵 |
| 3 | 행위는 봤고 결과를 놓쳤다 | 구조 이관 → 게이트 스코프 | 🔊 RED 는 이미 울고 있다 |
| 4 | **부정 단언에 값을 박았다** | **형제 슬롯이 경계 밖** | **🆕 RED 를 낼 수단이 없다** |

4번이 3번보다 나쁘다. 3번은 소리를 냈고 아무도 안 들었을 뿐인데,
4번은 소리를 낼 수단 자체가 없다.

### 실제 사례

```
organizations-list-three-column-p5.test.ts
  not.toMatch(/lg:grid-cols-\[1fr_280px\]/)        ← 폭을 박았다
LoadingSkeleton 은 1fr_300px 였다                   ← 20px 차이로 통과
```

`280px` 은 결정이 아니라 그때의 구현값이었다. 결정은 "우측 고정 컬럼 없음" 이다.
부정 단언에 구현값이 들어가는 순간 "그 값만 아니면 통과" 가 된다.

### 방향이 정반대라는 것이 핵심

```
긍정 단언에 옛 값을 박으면   RED 로 시끄럽게 실패한다   → 승계 노동이 생긴다
부정 단언에 옛 값을 박으면   조용히 통과한다             → 구멍이 생긴다
```

같은 실수인데 비용이 다르다. 그래서 **부정 단언을 더 엄격하게 본다.**

### 절차

부정 단언을 쓸 때마다 묻는다 — **"이 값이 결정인가, 그때의 구현값인가."**
구현값이면 가변 부분을 `\d+` / 문자 클래스로 열고, 열 수 없으면 형제 슬롯을
출현 수(`count === N`)로 묶는다.

## 3. §sweep-widen-then-filter — 부정 단언까지 확장

sweep 대상은 긍정 단언의 교체 대상만이 아니다. 부정 단언에 박힌 값도 sweep 대상이다.

승계 문법 (오늘 5회 적용):
- 잠그는 **결정**이 무엇인지 먼저 쓴다 (문자열이 아니라 결정)
- RED 를 보면 "무엇이 나빠졌나" 전에 "무엇이 좋아졌나" 를 본다 — 개선도 sentinel 을 깬다
- 은퇴시킬 때는 **역방향 잠금**을 같은 자리에 남긴다. 은퇴만 하면 새 결정이 무잠금이 된다
- 후계 표면을 이미 다른 sentinel 이 소유하면 **다시 핀하지 않는다** — 같은 사실을 두 곳이
  말하면 그것이 다음 갈라짐의 씨앗이다

## 4. 프로브 설계 순서 (앞단 1번 추가)

```
1  🆕 무엇을 읽고 있는지 먼저 찍는다 — location.href · 응답의 라우트 식별자
2  앵커가 소스에 몇 번 나오는지 센다 (주입 대상 파일 기준으로)
3  주입 후 문자열이 그 단언을 실제로 깨는지 눈으로 대조한다
4  그 다음에 실행한다
```

1번이 맨 앞인 이유: 대상 자체가 틀리면 계수로도 대조로도 안 잡힌다.
오늘 배포 확인 프로브가 `location.pathname` 을 fetch 하면서 signin 리다이렉트를
몰랐고, 세 문자열이 전부 `[]` 로 나와 "미배포" 로 오보할 뻔했다.
양성 대조군도 `[]` 였던 것이 유일한 구조 신호였다.

### 4-b. 개념을 정규식으로 재현하지 말고, 그 개념을 소유한 명령에게 물어라

게이트를 만들 때 "git 트레일러는 줄 맨 앞 + 콜론" 같은 **내 지식을 정규식으로 옮기면**
맞아도 근거가 내 머리다. 그 개념을 정의하는 도구가 있으면 그 도구에게 묻는다.

```
내 지식      /^Co-Authored-By[[:space:]]*:/          맞을 수도 · 근거는 추측
결정적 축     git interpret-trailers --parse          git 자신이 트레일러라고 부르는 것
```

실측(2026-08-26 · commit-msg 게이트 경계 검증):

```
Co-Authored-By: …          → 파싱됨      훅 exit 1  ✅ 일치
co-authored-by: …          → 파싱됨      훅 exit 1  ✅ 일치
  Co-Authored-By: … (들여씀) → 빈 출력    훅 exit 0  ✅ 일치 (git 도 트레일러로 안 본다)
```

들여쓴 형태를 통과시킨 것이 **느슨한 게 아니라 정확한 것**임을 git 이 증명했다.
추측이었다면 "혹시 몰라 막자" 로 넓혔을 것이고 그건 표면을 잠그는 쪽이다.

🔑 §4 의 1번(무엇을 읽고 있는지 먼저 찍는다)과 같은 자리다 — 대상의 정의를
   내가 재현하는 순간 그 재현이 검증 대상이 되고, 아무도 그것을 검증하지 않는다.

### 4-c. 게이트의 첫 테스트 케이스는 그 게이트를 도입하는 커밋 자신이다

commit-msg 게이트 첫 판은 `grep -qi 'Co-Authored-By'` 로 **문자열**을 막았고,
그 훅을 도입하는 커밋 본문이 조항을 설명하느라 그 이름을 쓰는 바람에 자기 자신을
거부했다. 첫 사용에서 100% 확률로 드러났다.

```
자기 자신에게 오탐   첫 사용에서 즉시 · 만든 사람이 원인을 안다
남의 커밋에서 오탐   며칠 뒤 · "게이트가 성가시다" 로 읽혀 꺼질 수 있다
```

🔑 게이트를 만들면 **그 게이트를 도입하는 커밋/변경 자신을 첫 케이스로 통과시켜 본다.**
   통과하면 실전 첫 통과가 이미 확보된 것이고, 막히면 그 자리에서 경계를 고친다.

## 5. 배포 확인 (§deploy-marker-is-not-build-time 폐기 · 정정)

```
① /api/health 의 manifestGeneratedAt > 커밋 시각    주축 · 인증 불필요 · 1회 호출
② 그 라우트 page 청크에 바뀐 문자열이 있는가          보조 · 인증 벽 안 · 양성 대조군 필수
```

①의 한계: `커밋 시각 < 마커` 는 "그 사이에 빌드가 있었다" 이지 "그 커밋이 그 빌드에
들어갔다" 가 아니다. **필요조건이지 충분조건이 아니다.** main 단선일 때만 무해하고,
브랜치가 늘면 ②가 필요해진다.

②의 필수 조건: `hits=[]` 는 미배포와 프로브 실명을 구분 못 한다. 이미 배포된 것이
확실한 같은 문자열을 다른 라우트에서 먼저 잡아 프로브의 시력을 증명한 뒤 판정한다.

## 6. 소스는 봤고 화면은 안 봤다

오늘 조직 트랙에서 sentinel 을 40건 넘게 세웠는데, 아래 셋은 **하나도 못 잡았고**
화면을 보자 즉시 나왔다.

```
로딩 스켈레톤이 옛 레이아웃          로딩 중에만 보인다 (관측 창 수백 ms)
요약 바 ↔ KPI 카드 중복              두 요소가 세로로 인접해야 보인다
캡션이 없는 메뉴를 가리킴            멤버 1명 상태에서만 보인다
```

세 조건 다 소스 읽기로는 재현이 안 된다. **화면에서만 보이는 것은 적어두지 않으면
다음에도 sentinel 이 침묵한다.**

### 관측 창을 만드는 법

관측 창이 짧으면 인위적으로 늘리되, **관측 도구가 리셋되지 않는 경로**를 고른다.

```js
// 로딩 스켈레톤을 붙잡은 방법 (2026-08-26)
window.__origFetch = window.fetch;
window.fetch = async (...a) => {
  const u = typeof a[0]==='string' ? a[0] : (a[0]&&a[0].url)||'';
  if (u.includes('/api/organizations')) await new Promise(r=>setTimeout(r,6000));
  return window.__origFetch(...a);
};
// 전체 리로드가 아니라 **클라이언트 내비게이션**으로 간다 — 리로드면 패치가 날아간다
document.querySelector('a[href="/dashboard/organizations"]').click();
```

⚠️ 프로브는 원복하고, 원복됐는지를 프로브 **밖에서** 확인한다
(`window.fetch.toString().includes('[native code]')`).

⚠️ 안 보이면 "고쳐졌다" 가 아니라 **"못 봤다"** 로 보고한다.
