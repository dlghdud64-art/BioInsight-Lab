### 6차 검증의 한계 (중요)

판정 기준을 미리 적어두고("850,000 으로 바뀌면 해소") 통과했다. 실측:
```

/api/budgets/[id]    usage {totalSpent 850,000 · remaining 4,150,000 · usageRate 17}
예산 관리 화면        현재 비용 ₩850,000 / ₩5,000,000 · 소진율 17%
```

⚠️ **그러나 이 GREEN 은 기간 산출까지 검증하지 않았다.**
`app/api/budgets/[id]/route.ts` 의 집계 창은 여전히 `yearMonth` 로 8/1~8/31 을 만든다.
이번 구매가 8/18 이라 **우연히** 창 안에 들어왔다. 9월 이후 구매는 상세에서만 누락된다.
→ 대기열 ⑤. 이 항목은 "GREEN 에 가려진 결함"이며 다음 세션이 통과 기록만 보고 닫지 말 것.

## 3. 7차 — 판정 대기 (A)/(B)

**문제**: 발주 생성(`POST /api/orders`)은 `quote.totalAmount || Σ lineTotal` 로 금액을 잡는다.
공급사 회신 단가는 그 어느 쪽에도 얹히지 않아 0 → `INVALID_AMOUNT` 400.

- **(A) 회신 확정 기록** — 선택된 회신의 단가를 `Quote`/`QuoteListItem` 에 확정 기록.
  발주·예산·감사가 같은 숫자를 본다. 발주는 대외 문서라 금액이 흔들리면 안 된다.
  ⚠️ **선행: "어느 회신을 확정으로 볼지" 정의가 없다.** 현재 UI 에 회신 선택 단계가 없다.
- **(B) 발주 시 파생 계산** — 저장 0, 즉효. 대신 회신이 바뀌면 발주 금액이 따라 움직인다.

🛑 **선택 정의가 먼저다. 기능부터 만들지 말 것.**
🛑 **(A) 미정인 동안 주문 접수는 400 으로 막혀 있다 — `dead button` 이 아니라 `차단 상태` 다.**
   (dead button 금지 조항을 근거로 급히 열지 말 것. 금액 정의 없이 여는 것이 더 위험하다.)
