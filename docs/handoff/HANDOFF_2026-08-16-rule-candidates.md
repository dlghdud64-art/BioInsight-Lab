CLAUDE.md 조항은 **4건 그대로**다. 여기 있는 셋은 근거를 쌓는 중이고,
각 항목의 **승격 조건**이 충족될 때 CLAUDE.md 로 올린다.

왜 커밋 body 가 아니라 여기인가:
- 커밋 body 는 읽히지 않는다. 이 세션에서 두 번 확인된 형태다.
- `"N회차 나오면 승격"` 이라는 조건 자체가 **어딘가에 적혀 있어야** 발동한다.
- B 트랙이 닫혔고 다음은 다른 트랙이다. 트랙이 바뀌면 근거 맥락이 흐려진다.

## 후보 ① §Sentinel 3원칙 ③ 보강 — 주입 범위 = 단언 창의 union

```
🛑 주입 범위 = 단언 창의 union.
   표면이 N개 파일이면 N개 전부에 주입한다.
   /g 없는 replace 는 첫 건만 바꾼다.
```

**근거 2회** — 둘 다 프로브가 6/N 으로 나왔고 원인이 주입 범위였다:

| 회차 | 트랙 | 결과 | 원인 |
|---|---|---|---|
| 1 | C 트랙 (§analytics-tabs) | 6/8 | `/g` 누락 — 주석만 치환, JSX 는 그대로 |
| 2 | B 트랙 (§reorder-handoff) | 6/9 | 1d 표면 2파일 중 1개만 주입 → 남은 파일이 통과시킴 |

⚠️ C 트랙 1차는 **단언 결함**(접두사·창 시작점·대체 매칭)이었고 B 트랙 1차는
**프로브 결함**이었다. 원인은 반대인데 형태가 같다 — 주입 범위와 단언 창이 안 맞음.

**승격 조건: 3회차.**

## 후보 ② §Sentinel 4원칙 ④ **방향** 보강 — 전파 경로는 가른다

```
④ 본문   같은 값을 쓰는 다른 요소가 대신 매칭한다 → 토큰 단위로 세지 말고 **분기 단위로 묶는다**
보강     🛑 반대 방향도 있다 — **전파 경로는 OR 로 묶지 말고 각각 단언한다.**
         경로가 둘이면 하나가 끊기는 것도 회귀다.
```

**근거 1회** (`87642da5`):

```ts
// 구 — OR 로 묶었다
expect(src).toMatch(/notes:\s*reason|specialNotes:[^\n]*\$\{reason\}/);
// → `notes: reason` 을 끊어도 specialNotes 가 대신 매칭해 GREEN (프로브 실측)

// 신 — 각각 단언
expect(src).toMatch(/notes:\s*reason/);
expect(src).toMatch(/specialNotes:[^\n]*\$\{reason\}/);
```

🛑 **④ 본문과 방향이 반대라서 따로 적어야 한다.** 대상이 다르다:

```
토큰   같은 창의 형제 요소가 같은 값을 쓴다   → 묶는다(분기 단위)
경로   서로 다른 계약이 각각 존재한다        → 가른다(개별 단언)
```

묶을 것과 가를 것을 구분하지 않으면 ④가 OR 남용의 근거로 오독된다.

**승격 조건: 2회차.**

### 🛑 왜 3회차인데 안 올렸나 — 다음 세션이 "3회인데 조항이 없네" 하지 않도록

```
비용이 작다.  tsc·esbuild 가 **즉시** 잡는다. 세 번 다 그 자리에서 검출·복구됐다.
잠재 결함이 아니다. 조용히 통과하는 형태가 아니라 빌드가 멈추는 형태다.
조항 인플레.  이번 세션에 조항 4건 신설 + 보강 후보 2건. 다섯 번째를 올리면
              조항 자체가 안 읽힌다 — 그 판단을 총괄이 이미 내렸다.
```

**승격 조건: `tsc`·`esbuild` 가 **못 잡는** 형태가 나오면.**
(예: 문자열 리터럴 안에서 조기 종료돼 파싱은 통과하는데 의미가 바뀌는 경우)
