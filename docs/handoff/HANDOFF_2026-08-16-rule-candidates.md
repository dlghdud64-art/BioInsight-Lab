## ✅ 승격 완료 2026-08-16 — 3회차 충족

🛑 후보 ③과 달리 **보류하지 않은 이유**: 이 형태는 **아무도 안 잡는다.**

```
후보 ③   tsc·esbuild 가 즉시 잡는다 → 빌드가 멈춘다 → 보류 정당
후보 ①   아무도 안 잡는다. 프로브가 GREEN 을 내고 끝난다
          3회 다 사후에야 사람이 눈치채서 드러났다
```

그리고 결과가 결정적이다:

```
프로브 GREEN = "단언이 검출력 있다" 는 결론
그 결론이 틀리면 → 검출력 없는 단언이 land 된다 → 게이트가 있는데 안 잡는다
```

**③(검출력 실증) 자체가 무력화되는 형태**라, 보강이 아니라 ③을 성립시키는 조건이다.
조항 인플레보다 이쪽이 비싸다.

## 후보 ② §Sentinel 4원칙 ④ **방향** 보강 — 전파 경로는 가른다

```
④ 본문   같은 값을 쓰는 다른 요소가 대신 매칭한다 → 토큰 단위로 세지 말고 **분기 단위로 묶는다**
보강     🛑 반대 방향도 있다 — **전파 경로는 OR 로 묶지 말고 각각 단언한다.**
         경로가 둘이면 하나가 끊기는 것도 회귀다.
```

**근거 1회** (`87642da5`):

```ts
// 구 — OR 로 묶었다
expect(src).toMatch(/notes:\s*reason|specialNotes:[^\n]*\$\{reason\}/);
// → `notes: reason` 을 끊어도 specialNotes 가 대신 매칭해 GREEN (프로브 실측)

// 신 — 각각 단언
expect(src).toMatch(/notes:\s*reason/);
expect(src).toMatch(/specialNotes:[^\n]*\$\{reason\}/);
```

🛑 **④ 본문과 방향이 반대라서 따로 적어야 한다.** 대상이 다르다:

```
토큰   같은 창의 형제 요소가 같은 값을 쓴다   → 묶는다(분기 단위)
경로   서로 다른 계약이 각각 존재한다        → 가른다(개별 단언)
```

묶을 것과 가를 것을 구분하지 않으면 ④가 OR 남용의 근거로 오독된다.

**승격 조건: 2회차.**
