**제품:** LabAxis · 입고 관리 모바일 웹 (`/dashboard/receiving`, viewport < 768px)
**범위:** 입고 리스트(RCV 카드 통합) + 문서 첨부 시트(dead button 배선)
**프로토타입:** `모바일 입고 관리 개선.dc.html` — 1a(화면) · 1b(첨부 시트)

## 0. 진단 (왜 고치나)

1. **문서 첨부 = dead button** — 클릭해도 아무 동작 없음(no-op). LabAxis 원칙 위반.
2. **같은 RCV가 카드 3장으로 분열** — RCV-2026-0031이 "문서 누락 / 재고 반영 차단 / 보류 품목"으로 나뉘고, "반영 차단"은 나머지의 **결과 요약**인데 대등한 카드로 나열. CTA 2개가 동일한 `문서 첨부`라 어느 걸 눌러야 할지 모호. 원인 해결 → 결과 카드 자동 소멸 관계가 화면에 없음.
3. **차단 카드가 배경까지 분홍 채색** — 다른 화면에서 확정한 "흰 카드 + 레드 포인트만" 원칙 위반. 풀폭 파란 CTA 반복으로 위계 소실.

## 1. 입고 리스트 (1a) — RCV 단위 통합 카드

### 카드 구조 (RCV 1건 = 카드 1장)
- 헤더: 상태 배지(`⚠ 반영 차단` — 칩만 레드 `#fef2f2/#b91c1c`) + 경과(`◷ 24시간 초과` 레드 텍스트)
- 타이틀: RCV 번호 + 메타(공급사 · 라인 수 · 도착일)
- **차단 사유 체크리스트** — "반영까지 남은 일 · N" 헤더 + "해결되면 자동으로 지워져요":
  1. `필수 문서 미첨부` (라인명 · 문서 종류) → CTA `첨부 ›` (primary)
  2. `보류 N건 미해결` (보류 검사 실행 대기) → CTA `검사 ›` (outline)
  3. `검수 완료` — 선행(1·2) 미해결 시 회색 비활성 + "1·2 해결 후 진행돼요"
- 최종 CTA: `재고 반영 · N건 해결 후 가능` (비활성, **사유 인라인**). 전부 해결 시 `재고 반영 ›` primary로 활성.

### 규칙
- **배경 채색 금지** — 흰 카드 + 보더 `#e6eaf0`. 레드/앰버/그린은 배지·번호 칩·텍스트에만.
- 사유 번호 칩: 문서=레드 `#fef2f2/#b91c1c`, 보류=warm warning(**yellow 토큰** `#fef9c3/#a16207`), 대기=그레이 `#f1f5f9/#94a3b8`.
- 해결된 사유는 줄 소멸(취소선 잔류 금지), 카운트·최종 CTA 동시 갱신.
- 반영 준비된 RCV(`✓ 반영 준비됨` 그린 칩)는 별도 카드, CTA `재고 반영 ›` 활성.
- KPI 2장(문서 대기/반영 가능) + 필터 칩(전체/문서 대기/반영 가능)은 현행 유지. KPI 숫자는 체크리스트 상태와 동일 소스.

## 2. 문서 첨부 시트 (1b) — 배선

`첨부 ›` → 바텀 시트(그랩바):
1. 헤더: 문서 첨부 / `RCV 번호 · 라인명` — **누락 라인·문서 종류가 이미 선택된 컨텍스트로 오픈**
2. 필수 문서 리스트: 완료 건(그린 ✓ + 파일명·업로드일 + `보기`) / 미첨부 건(파란 점선 드롭존)
3. 드롭존: 문서명(COA 등) + `📷 촬영`(primary, 모바일 우선) + `파일 선택` · PDF, JPG
4. 안내: "업로드되면 차단 사유에서 자동으로 지워지고 활동 로그에 기록됩니다"
5. 완료 CTA: 남은 필수 문서 있으면 비활성 + 사유(`첨부 완료 · COA 업로드 후 가능`)

### 배선 규칙 (필수)
- 업로드 성공 = **서버 반영 확인 후** 체크리스트 줄 소멸 + KPI "문서 대기" 감소. **프론트만의 성공 토스트 금지.**
- 업로드 실패 시 에러 상태 + 재시도. 부분 업로드(1/2)는 남은 건수 유지.
- 모든 첨부·삭제는 활동 로그 기록.

## 3. 데이터 모델

```ts
Receiving = {
  id,                        // RCV-2026-0031
  vendor, lineCount, arrivedAt,
  blockers: Blocker[],       // 순서 = 해결 순서
  status: 'blocked'|'ready'|'reflected',   // 서버 산출
}
Blocker =
  | { kind:'doc',        line, docType, resolved }
  | { kind:'quarantine', count, resolved }
  | { kind:'inspection', dependsOn:['doc','quarantine'], resolved }

// 파생 (서버)
status = blockers.every(b=>b.resolved) ? 'ready' : 'blocked'
```

## 5. QA 체크리스트

- [ ] RCV 1건 = 카드 1장 (결과 요약 카드 없음)
- [ ] 차단 카드 배경 채색 없음 — 흰 카드 + 포인트만
- [ ] 체크리스트 순서·의존 관계 표시(3번은 1·2 해결 전 비활성)
- [ ] `첨부 ›` → 시트 오픈(라인·문서 종류 프리셋), no-op 없음
- [ ] 업로드 성공 시 서버 반영 후 줄 소멸 + KPI 감소 (front-only success 0)
- [ ] 최종 `재고 반영` 비활성 사유 인라인, 전부 해결 시 활성
- [ ] 보류 사유는 yellow 토큰(amber sentinel 준수)
- [ ] 촬영/파일 선택 모두 동작, 실패 시 재시도
- [ ] 터치 타겟 44px 이상
