## 0. 원인 (실측)

1. **no-op**: `MobileDetailSheet`의 `AI 재발주 검토` → `onReorder` → `openReorderReview()` → `openContextPanel(inv,"reorder")` (inventory-content.tsx L1624·L394). ContextPanel은 데스크톱 사이드 패널이라 모바일 뷰포트에서 미렌더 → 상세 시트만 닫히고 아무것도 안 뜸.
2. 데스크톱 ContextPanel의 `onReorder`(L2881~)에는 이미 올바른 분기 존재: `qty && !blocked → openReorderReviewSheet(match)`. **모바일 경로만 이 분기를 안 탐.**
3. `InventoryReorderReviewSheet` 래퍼는 `recommendedQty`가 null/0이면 `data=null` → 시트 자체 미표시. 추천 쿼리(`reorder-recommendations-for-highlight`) 로딩 중/실패 시 **침묵 no-op**.
4. **헤더 사라짐**: 바텀시트(Sheet side="bottom") scrim이 fixed 헤더까지 덮음 → 시트가 max-h-85vh라 상단이 검은 띠.

## 1. 배선 수정 (release blocker)

`inventory-content.tsx` L1624 모바일 `onReorder`를 ContextPanel과 동일 분기로:

```tsx
onReorder={(inventory) => {
  const qty = reorderRecommendedQtyFor(inventory.id);
  const blocked = reorderBlockReasonsFor(inventory.id);
  if (qty && blocked.length === 0) { openReorderReviewSheet(inventory); return; }
  if (blocked.length > 0) { openReorderBlockedSheet(inventory, blocked); return; } // §3
  openReorderReviewSheet(inventory, { fallbackQty: Math.max(0, (inventory.safetyStock ?? 0) - inventory.currentQuantity) }); // §2
}}
```

`InventoryReorderReviewSheet`는 이미 content-level(모바일에서도 렌더) — 추가 마운트 불필요.

## 2. 침묵 금지 — 추천 미산출 시 (시안 ②)

- 추천 쿼리 **로딩 중**: CTA를 비활성 로딩 상태(`추천 수량 계산 중…` + 스피너, bg-blue-300)로. 산출되면 자동 활성.
- **미산출/실패**: `data=null → 미표시` 대신 **fallbackQty = max(0, safetyStock − currentQuantity)** 로 시트 오픈, 시트 안에 `AI 추천 미산출 · 안전재고 기준 수량` 배지로 출처 명시(가짜 AI 라벨 금지 — canonical 아님을 표기).
- fallbackQty도 0이면 CTA 미생성(dead button 방지) — 이 케이스는 action.type이 reorder가 아니므로 실제 발생 없음.

## 3. 중복 위험 소프트 게이트 (시안 ③) — 하드 차단 금지

`blockReasons.length > 0`이면 재발주 시트 앞에 **확인 바텀시트**를 끼움 — 차단이 아니라 게이트:

- yellow 카드(`#fffbeb/#fde68a/#92400e`) 타이틀 `중복 발주 위험이 있습니다` 한 줄(대시 문장부호 금지) + 사유별 흰 미니 카드(제목+보조설명) 스택 + 정량 근거 문장(입고 반영 시 잔여 부족분).
- 액션 2개: `진행 중 발주 보기`(outline, 해당 PO 라우팅) + **`그래도 재발주 검토 진행`(primary)** — 진행 중 발주가 수요를 못 덮는 케이스(증산·분할 납품·취소 예정)가 실재하므로 경로를 막지 않는다.
- 진행 선택 시 재발주 검토 시트(§4)로 진입하되, 근거 섹션에 **입고 예정 수량을 함께 표시**(중복 발주를 알고 결정하게) + 결정 기록에 override 사유 남김.
- 폐기 선행 등 진짜 불가 사유(정책상 진행 불가)만 예외적으로 primary 미생성 — blockReasons에 severity(soft/hard) 구분 필드 추가 권장, 현재 사유는 전부 soft.

## 4. 재발주 검토 시트 구성 (시안 ①)

순서: AI 권장 pill + 상태(● 안전재고 미달, rose) → 품목명 + 현재/부족 요약 → **권장 발주 수량 스테퍼**(± 34px, 근거 캡션 "부족 9 + 여유 1" = recommendationBreakdown) → **최근 구매 공급사**(vendorName · unitPrice · 구매일, useReorderRecommendation 기존 소스) → CTA 2개: `견적 요청 초안 만들기`(primary, 기존 quote-draft 경로) + `공급사 소싱에서 찾기`(outline, `/app/search?q=` 기존 배선 재사용).

## 5. scrim/헤더 (시안 공통)

- 바텀시트 overlay를 `top: var(--header-h, 56px)`로 — 헤더는 항상 보임(뒤로가기·타이틀 유지). SheetContent가 아니라 **overlay만** 오프셋.
- 상세 시트(MobileDetailSheet)와 재발주 시트 동일 적용. z-index: 헤더 > overlay > 페이지.
- 전환: 상세 시트 → 재발주 시트는 상세를 닫고 열기(중첩 시트 금지).

## 7. 데스크톱 표면 교체 (v2 — release blocker)

**문제(실화면):** 웹에서 행 `재발주` 클릭 시 모바일용 바텀시트가 **데스크톱 전폭(2560px)** 으로 그대로 뜼 — 버튼도 전폭, `보관 위치 —`가 빈 공간에 부유, 정보 밀도 붕괴.

**수정:** 뷰포트 분기 — 같은 내용, 다른 그릇:
- **모바일(<768px):** 바텀시트 유지 (§1~5).
- **데스크톱:** 우측 패널(품목 브리핑 ContextPanel과 동일 폭, ~380–420px) 또는 중앙 모달 max-width 480px. 기존 `재발주안 검토` 우측 패널 표면이 이미 있으므로 **그쪽으로 라우팅 재사용** 권장 — 신규 표면 금지(중복 표면).
- 버튼은 그릇 폭 기준 전폭 2단 스택(견적 요청 초안 primary / 소싱 찾기 outline) — 2560px 전폭 버튼 금지.
- 빈 필드 표기 규칙 (전 표면 공통 — 재발주안 요약 시트 포함): 대시(—/ㅡ) 노출 금지. **운영상 의미 있는 공백**(보관 위치·COA 등)은 `미지정`으로 정직 표기(앰버 `#b45309`) + 채우기 액션, **단순 미입력**(용도·납기 등)은 필드 자체 숨김. 현행 재발주안 요약의 `보관 위치 —`가 대표 사례 — `미지정`(앰버)으로 교체.
- `바로 발주`(green, 준비 중) — 비활성 사유가 하단 작은 회색 텍스트로만 있음. 기능 미제공이면 버튼 미생성(dead button 금지), 제공 예정이면 disabled + 인라인 사유 배지.
