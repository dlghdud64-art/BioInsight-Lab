## 🛑 sha256 은 이관 시점 **1회성 증명**이다 — 갱신할 때 다시 뜨지 말 것

이관 전에는 이 문서들이 게이트 밖이라 해시가 유일한 잠금이었다.
이관 후에는 **git 이력이 버전 관리를 대신하고 되돌림은 diff 로 잡힌다.**
매 갱신마다 해시 전이를 기록하면 갱신에 **세금**이 붙고, 그 압력이 정확히
`md_stale_em_dash` 가 두 배치 동안 남아 있던 이유다.

위 해시는 **"Desktop 원본과 repo 사본이 같다"만** 증명한다. 그 이후는 git 이 안다.

## 🛑 단일 소스 — Desktop 사본은 이 시점부로 정본이 아니다

Desktop 원본은 삭제하지 않는다(도구 제약). 그러나 **정본은 repo 사본이다.**
Desktop 사본을 고치면 갈라진다. **명세 변경은 repo 에서만.**

## 시안 HTML 은 이관 대상 아님

시안은 **"안 바뀌어야 하는 것"** 이라 sha256 앵커가 방어로 맞다.
md 는 **"바뀌어야 하는 것"** 이라 해시가 마찰이 된다. **축이 다르다.**
시안 HTML(약 20개 × 22MB)은 Desktop 유지 + fixture 의 `source_sha256` 앵커 존치.

## 등급 — `미판정` 은 빈칸이 아니다

이번 배치 확정 **5건**(정본 3 · 파생 1 · 은퇴 1), 나머지 **20건은 `미판정`**.
빈칸으로 두면 검사 밖이지만 `미판정` 은 **명시적 대기열**이다 — 축을 적으면 미측정도 자산이다.
