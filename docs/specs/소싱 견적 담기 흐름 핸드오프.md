**시각 truth:** `소싱 견적 담기 흐름 개선 (단독).html` — 1a 제품 상세(담김 상태) · 1b 발송 준비 딥링크 · 1c 재발주 → 소싱 진입

## 0. 현행 문제 (2026-08-09 배포본 확인)

1. **담기 순간 3중 피드백** — 우측 레일 담김 버튼 + 하단 sticky 바(견적함 1건 · 비우기 · 견적 진행) + 우하단 toast가 동시 노출.
2. **견적 진행 → 리스트 덤핑** — `/dashboard/quotes` 리스트로 이동, 방금 만든 초안이 발송 대기 행 7건 중 하나로 섞임. 다음 행동 불명.
3. **추천 섹션 2중화** — 대체품 추천 + 연관 추천 제품이 간격 없이 연달아 (화면 절반 점유), 연관 추천의 비교·피드백 버튼은 배선 불명.
4. 우측 레일에 영업 문의·상시 안내문 잔존 (§소싱 제품 상세 핸드오프 v2 §7 정리 대상).

## 1. 제품 상세 (1a)

- **연관 추천 제품 섹션 제거** — 검색 결과/홈 표면으로 이관. 상세에는 대체품 추천만(근거 칩 포함, v2 §6).
- 섹션 간 간격 20px, 대체품 카드 간 12px 통일.
- **담기 피드백 = 레일 1곳**: 담기 클릭 → 버튼이 `✓ 담김 · 견적함 보기`(그린)로 전환 + 아래 `견적 진행 →`(블루) 생성. toast 삭제. 하단 sticky 바는 **견적함 2건 이상일 때만** 노출(여러 품목 묶음 진행 용도).
- 레일 구성: 견적가 안내 품목 → 담김 상태 버튼 → 견적 진행 → 캡션 1줄("담긴 N건으로 발송 준비를 시작합니다"). 영업 문의 행 삭제.
- 작성 중 견적 존재 시 yellow 카드(`작성 중인 견적 열기`) 유지 — 단 견적 진행과 같은 목적지(§2).

## 2. 견적 진행 = 발송 준비 딥링크 (1b — 핵심)

- `견적 진행` / `견적 요청서 만들기` / 리스트 카드 CTA 전부 → **`/quotes/{rfqId}/prepare` 직행**. 리스트 경유 금지.
- 화면 = **재발주→견적 핸드오프 1c와 동일 컴포넌트 재사용** (진입 출처 라벨만 다름: "방금 소싱에서 담김" vs "재고관리에서 생성"):
  - 헤더: RFQ 번호(mono) + 출처 + `나중에 하기 · 발송 대기로 저장`
  - 3스텝 pill: ✓ 품목 확정 → ② 공급사 지정(활성) → ③ 발송
  - 품목 카드: `방금 담김` 배지 + 2초 하이라이트 + 수량 변경
  - 공급사 지정 패널: 검색 + 이메일로 추가 + **이전 거래 공급사 추천 1줄**(카테고리 매칭, `지정` 버튼)
  - CTA: 지정 전 disabled + 사유 라벨(`발송 검토로 · 공급사 지정 필요`), 지정 시 발송 검토 모달로 연속
- 이탈 시 리스트 카드 상태 `공급사 지정 필요`(yellow pill) + CTA로 이 화면 복귀.

## 3. 재발주 → 소싱 진입 (1c — 신규)

재발주 시트의 `공급사 소싱에서 먼저 찾기` 클릭 시:
- `/app/search?q={품목명}&reorder={reorderId}` — 검색어 자동 입력.
- **컨텍스트 배너**(블루): "재고관리 재발주안에서 왔습니다 · {품목} · 권장 N개 · 검색어와 견적함에 자동 반영됨" + `재발주안으로 돌아가기` 링크.
- **견적함 자동 담김**: 해당 품목 + 권장 수량(재고관리 산출) + `재발주 연동` 배지 + 수량 스테퍼에 "재고관리 권장" 캡션.
- 검색 결과에서 원 품목 행에 `재발주 대상` 배지, 담긴 상태는 `✓ 견적 후보 · N개`.
- **양방향 동기화**: 견적 요청서 생성 시 재발주안 상태 → `견적 진행 중` (이중 재발주안/이중 견적 생성 방지). 견적함 레일 하단에 예고 캡션.
- 요청서 생성 후 → §2 발송 준비 딥링크로 연속.

## 4. 배선 규칙

- 담김 상태는 quote-cart 레코드에서 파생(front-only 금지). 담기 해제 시 레일 원복.
- sticky 바 노출 조건: `cartItems.length >= 2`.
- reorder 파라미터 유실 금지 — 견적 생성까지 전달되어 RFQ↔재발주안 링크 저장.
- em dash 금지, 날짜 YYYY. M. D., 코드 IBM Plex Mono, 전역 tabular-nums.
