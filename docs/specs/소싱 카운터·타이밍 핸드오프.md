# 소싱 — 카운터 중복 정리 · 담기 타이밍 완화 (핸드오프)

**제품:** LabAxis · 소싱 (`/app/search`)
**프로토타입:** `소싱 카운터·타이밍 정리.dc.html` (1a 헤더 · 1b 하단 바 · 1c 타이밍)

---

## 0. 문제

1. 같은 수치가 **세 곳**에 중복 — 결과 헤더(`비교 후보 2 / 견적 후보 3`) · 우측 레일 탭(`견적함 3 / 비교함 2`) · 하단 바(`비교 2 / 견적 3`).
2. 헤더 카운터는 **클릭 불가한 죽은 텍스트** (조언 문구 "비교 후 요청 전환이 적절합니다"도 실행과 분리).
3. 하단 바가 **2줄**로 각자 카운트·CTA를 가져 시선이 분산.
4. 담기 시퀀스 총 ~600ms로 **너무 빨라** 어디로 담겼는지 추적 불가. 토스트가 **상단 대형 박스**로 검색창을 가림.

## 1. 결과 헤더 (1a)

- 헤더는 **결과 맥락만**: `검색 결과 4건` + 매칭 품질(`품명 일치 3 · 가격 공개 1`) + 정렬/필터/재고.
- `비교 후보 N` / `견적 후보 N` 카운터 **삭제**.
- 조언 문구는 실행 위치(하단 바)로 이동.

## 2. 하단 바 — 2줄 → 1줄 (1b)

- 하단 바가 **카운트 단일 소스**.
- 좌측: `견적함 N` / `비교함 N` **세그먼트**(활성만 파란 배지 `#2563eb`, 비활성 `#cbd5e1`) — 클릭으로 레일 전환.
- 중앙: 담긴 품목 요약(`PBS-3 외 2건`) + 가격 미정 경고 칩(yellow `#fefce8/#a16207`). 기존 `차단 3` 레드 배지는 과경고 → yellow `가격 미정 3`으로 완화.
- 우측: 조언 문구 + `비교 리포트`(보조) + `견적 요청서 만들기`(green `#16a34a`, 주 CTA).
- 우측 레일 탭 배지는 **레일이 열려 있을 때만** 유지.

## 3. 담기 타이밍 (1c)

| 단계 | 현재 | 개선 | 비고 |
|---|---|---|---|
| 버튼 모프 | 450ms | **380ms** | 즉시 반응 유지 |
| 플라잉 칩 이동 | 550ms | **820ms** | 시선 추적 구간, 살짝 호(arc) 궤적 |
| 도착 hold | 0 | **120ms** | 칩 소멸↔배지 범프 사이 호흡 |
| 배지 범프 | 450ms | **520ms** | 1→1.4→1 + 글로우 동시 |
| 토스트 | 상단 대형 1.8s | **하단 pill 2.6s** | ✕ 없이 자동 소멸, 검색창 미가림 |

- 총 ~600ms → **약 1.3s** (범프는 이동과 일부 겹침).
- 토스트: 다크 pill `#0f172a`, `견적 후보에 담았어요 · 가격은 견적 요청 후 확정`.
- `prefers-reduced-motion`: 이동·범프 생략, 상태 변화(모프·카운트)만.

## 4. QA

- [ ] 헤더에 담긴 개수 카운터가 없다
- [ ] 하단 바 1줄, 견적함/비교함 세그먼트로 레일 전환
- [ ] 카운트가 하단 바·레일에서 항상 일치(단일 소스)
- [ ] `차단 N` 레드 → `가격 미정 N` yellow
- [ ] 담기 총 시간 ≈1.3s, 칩 궤적이 목적지 배지에 정확히 도착
- [ ] 토스트가 하단 pill·2.6s·검색창 미가림
- [ ] reduced-motion 폴백
