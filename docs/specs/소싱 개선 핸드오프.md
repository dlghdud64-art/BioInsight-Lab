## 1. 견적 담기 마이크로 인터랙션

클릭 시 시퀀스 (총 ~600ms):
1. **버튼 모프** — `🛒 견적 담기`(파랑 채움) → `✓ 견적 후보`(연파랑 아웃라인), 팝 450ms `cubic-bezier(.34,1.56,.64,1)`. 다시 누르면 해제(토글).
2. **플라잉 칩** — 품목명 칩이 버튼 좌표 → 견적함(레일) 배지 좌표로 이동. `transform: translate` 550ms `cubic-bezier(.22,.9,.36,1)`, scale 1→0.35 + fade. 좌표는 `getBoundingClientRect` 실측(하드코딩 금지).
3. **배지 범프** — 견적함 카운트 변경 시 scale 1→1.45→1 (450ms) + 레일 1회 글로우(ring 확산 600ms).
4. **레일 항목 슬라이드 인** 300ms + `견적 요청서 만들기` CTA 활성 전환.
5. **토스트는 보조** — 하단 소형 pill 1.8s 자동 소멸("견적 후보에 담았어요 · 가격은 견적 요청 후 확정"). 화면 상단 중앙 대형 안내 박스 제거.

규칙:
- **비교 추가도 동일 문법** — 비교함으로 나는 칩은 보라 톤(`#6d28d9`)으로 목적지 구분.
- `prefers-reduced-motion` 시 플라잉·범프 생략, 상태 변화(모프·카운트)만.
- 피드백의 주인공은 목적지(견적함/비교함) — 토스트 의존 금지.

## 2. AI 비교 분석 리포트

### 관문 상태 (가격 보유 후보 < 2건) — 1a
- **전면 차단 금지.** 지금 분석 가능한 스펙 비교(제조사·규격·분류)는 즉시 표시, **가격·납기 행만 🔒 "견적 후 확정"** 잠금.
- 관문 스트립 1줄: 왜 잠김("가격·납기 분석은 견적 확보 후 완성돼요") + CTA `견적 요청 만들기 ›` + 자동 갱신 약속("회신 도착 시 리포트 자동 갱신").

### 데이터 상태 (확정안 · 1b)
1. **추천 요약** (최상단, 파란 강조 카드) — 추천 배지 + 제품명 + 이유 1문장 + 핵심 수치 3개(예상 절감/납기/리스크).
2. **비교 표** — 추천 열 ★·색 강조, **우위 값만 초록**(단가·납기). 행: 단가 · 납기 · 최소 주문 · 구매 이력.
3. **리스크 노트** — 최소 주문 과잉·단종·인증 등, yellow 토큰(`#fefce8/#a16207`). "단가만으로 비교하지 마세요" 같은 판단 보조.
4. **CTA `추천안으로 견적 요청 ›`** — 리포트가 실행으로 이어짐(읽고 끝 금지). 보조: 닫기.
5. 헤더에 신선도 표기("견적 회신 2건 반영 · 방금 갱신") — 회신 도착 시 자동 갱신.
6. 푸터 고지: "AI 분석은 참고용이에요 · 조건을 확인한 뒤 요청을 진행하세요".

## 3. 배선 규칙

- 담기/해제·리포트 갱신은 서버 반영 확인 후 UI 확정(front-only success 금지).
- 견적함/비교함 카운트는 하단 바·레일·리포트가 단일 소스.
- 리포트 CTA → 견적 요청서 생성 플로우 딥링크(추천 품목·수량 프리필).
