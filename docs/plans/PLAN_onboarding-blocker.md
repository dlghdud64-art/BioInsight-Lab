# §onboarding-blocker — 사용자를 받기 전에 반드시 닫아야 하는 목록

- **Status:** 운영 목록 (2026-08-12 개설, 호영님 지시)
- **성격:** 트랙이 아니라 **게이트**. 여기 열린 항목이 있으면 "사용자 앞에 세우기" 를 하지 않는다.

---

## 이 목록의 판정 기준

> **첫 고객이 걸릴 자리인가.**

버그 심각도가 아니라 **누가 언제 걸리는가**로 판정한다. 지금 실사용자가 없어 아무도
걸리지 않는 항목이라도, 사용자를 받는 순간 터진다면 여기 들어온다.
**"지금 안 터진다" 는 해결이 아니라 부재의 결과다.**

특히 다음은 자동 등재:
- 고객사가 **스스로 복구할 수 없는** 상태를 만드는 것 (복구가 DB 직접 수정뿐)
- 우리에게 **지원 요청이 오고 우리가 프로덕션 DB 를 손대야** 하는 것
- 로그인·조직 통제 등 **첫 5분 안에 닿는** 경로

---

## 열린 항목

### 1. §team-org-role-model — 팀 ADMIN 데드락

`docs/plans/PLAN_team-org-role-model.md`

**조직이 자기 팀에 대한 통제권을 잃는 구조.** 팀 생성자는 조건 없이 ADMIN 이 되고,
강등·제거·자진사퇴·팀 폐기가 전부 0 이었다 → 되돌리는 방법이 DB 직접 수정뿐.

| 상태 | |
|---|---|
| 작은 안 (자기 강등·나가기, 마지막 ADMIN 보호) | ✅ 완료 2026-08-12 |
| 큰 안 (조직 OWNER 권한 + `organizationId` 기록) | ⬜ 승인 대기 |

🛑 **작은 안으로 닫히지 않는다.** 퇴사자는 로그인하지 않으므로 여전히 회수 불가다.
**큰 안이 끝나야 이 항목이 닫힌다.**

### 2. §auth-provider-scope — 로그인 경로

`docs/plans/PLAN_auth-provider-scope.md`

첫 고객이 가장 먼저 닿는 자리. 상세는 해당 문서.

### 3. 온보딩에 조직 생성 단계가 없다 🆕 (2026-08-12 실측)

**가입 시 조직이 자동 생성되지 않는다** (`src/auth.ts` 에 organization 참조 0).
조직은 `POST /api/organizations` 명시 호출뿐이다.

→ 가입 직후 사용자는 **조직 미소속**이다. `Team.organizationId` 를 `required` 로
바꾸면 그 사용자는 **팀을 만들 수 없다.** 예산·권한 회수도 조직을 전제한다.

닫는 방법: 온보딩에 조직 생성(또는 초대 수락) 단계를 넣는다.
§auth-provider-scope 와 같은 층 — 첫 5분 안에 닿는 경로다.

### 4. 조직 `OWNER` 가 아무도 되지 않는다 🆕 (2026-08-12 실측)

`role: OWNER` 를 **DB 에 쓰는 코드가 repo 전수 0**. 조직 생성자는 `ADMIN` 이 된다
(`lib/api/organizations.ts`). 상세: §team-org-role-model 1-H ③-A.

파급 2건 — ⓐ 조직 생성 직후 화면은 `OWNER` 로 표시하나 DB 는 `ADMIN`(거짓 표시),
ⓑ `approver-routing` 의 OWNER 기반 승인자 선택이 **항상 fallback 으로 빠진다**.

**게이트 사유:** 최고 권한자가 없는 조직은 권한 회수·소유권 이전 경로가 없다.
§team-org-role-model 큰 안(조직 OWNER 권한)도 이 상태로는 dead code 다.

## 관련 (게이트 아님 — 참고)

- **§org-scope-ambiguity** — 다중 소속 시 `findFirst` 가 임의 조직을 집는다.
  전환기가 6개 라이브 화면에 있으므로 **이미 발생 중인 결함**이나, 오표시이지
  차단은 아니라 게이트가 아닌 트랙으로 둔다. 실사용자 유입 후 우선순위 재평가.
