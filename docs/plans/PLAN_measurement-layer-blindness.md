# §measurement-layer-blindness — 층을 안 세고 낸 등급은 **두 번 틀렸다**

- **Status:** 규칙 등재 (2026-08-14) · **실측 전 절차로 승격**
- **승격 경위:** §tenant-isolation-placeholder 실측에서 **연속 2회 등급 오류**.
  둘 다 원인이 같다 — 요청이 통과하는 층을 다 세지 않고 한 층만 보고 판정했다.

---

## 0. 규칙

> **격리·권한 실측은 요청이 통과하는 모든 층을 열거한 뒤 설계한다.**
> 층 목록을 명시하지 않은 실측은 착수하지 않는다.

### 층 목록 (이 repo, 2026-08-14 기준)

```
1. middleware.ts        matcher `/api/:path*` · `/api/admin/*` 는 User.role==='ADMIN' deny-by-default
2. enforceAction        조직 게이트 — (a)≡(b) 항등이라 거절 불가 (§tenant-isolation-placeholder)
3. 역할 게이트           ACTION_ROLE_MINIMUM — 조직 비교보다 **먼저** 반환한다
4. 라우트 자체 검사       organizationMember 조회 / userId 비교 / scopeKey·guestKey
5. 드리프트 500          §drift-masks-isolation — 차단이 아니라 판정 유예
```

## 1. 실제로 틀린 기록 (숨기지 않는다)

| 회차 | 오독 | 결과 |
|---|---|---|
| 1차 | 역할 게이트(3층) 조기 반환을 **"경로 미도달"** 로 읽음 | 조직 비교가 실행됐는지 판정 불가 상태에서 진행할 뻔함 |
| 2차 | 미들웨어(1층) 커버를 **"무방비"** 로 읽음 | 유출면을 11건으로 보고 → 실제 고객 도달 3건 |

2차가 더 무겁다. **미들웨어라는 실질 방어층의 존재 자체를 실측 설계에서 누락**했고,
그래서 라우트 레벨만 본 정적 분류가 런타임과 **5건 어긋났다**.

## 1.5 검증 도구 자신도 대상이다

> **검증 도구는 자기 자신을 대상에 포함시켜 1회 검증하기 전까지 결과를 채택하지 않는다.**

A4 단언은 작성 직후 `quotes/[id]/status` 를 "검사 없음"으로 분류했다 — 방금 넣은
검사를 못 읽은 것이다. 원인은 분석기 버그였다: `): Promise<{ ok: true } | ...> {` 의
**반환 타입 주석을 함수 본문으로 오인**해 헬퍼 본문이 `{ ok: true }` 로 잘렸다.
자기검증 조항이 없었으면 이 단언은 **통과하면서 아무것도 읽지 않는 상태**로 커밋됐다.

⚠️ **이번 세션 2번째**다 — 앞선 것은 `| tail` 파이프가 종료코드를 가려 실패를 성공으로
읽은 건이었다. 둘 다 "도구가 조용히 거짓말한다" 형태다.

따라서 모든 커버리지·분류 단언은 다음을 포함한다:
1. **자기검증** — 방금 고친 대상이 "고쳐진 것으로" 분류되는가
2. **corrupt→RED** — 각 인식 경로마다 1건씩 (커버 인식 / 검사 인식)
3. **열거 하한** — 수집이 0건으로 죽으면 단언이 조용히 통과하므로 하한을 건다

## 2. 절차

1. 실측 설계서에 **층 목록을 먼저 적는다**
2. 각 층에 **관문별 로그**를 심는다 — 결과(차단/통과)만으로는 어느 층이 판정했는지 못 가른다
   (§tenant-isolation-placeholder §0 로그 규칙의 일반화)
3. 차단이 나오면 **어느 층이 막았는지 기록**한다. "403" 은 증거가 아니다
4. 정적 분류는 **가설**이다. 런타임 실측이 판정이다

## 3. 스윕·단언에 적용

- **A5 런타임 스윕**: 요청마다 차단 주체 4분류 필수 —
  `미들웨어 / 라우트 검사 / 드리프트 500 / 미도달`. 4분류 없는 스윕 결과는 **채택 불가**
- **A4 재발 방지 단언**: 미들웨어 커버 경로를 own 으로 인식하되
  **프리픽스 하드코딩 금지** — `middleware.ts` 의 matcher 와 role 조건을 읽어 커버 집합을
  도출한다. 하드코딩하면 matcher 가 바뀔 때 단언이 **조용히 거짓말한다**
- corrupt→RED 실증은 **미들웨어 커버 경로 1건 + 라우트 검사 경로 1건 각각**.
  한쪽만 하면 커버 인식 로직 자체가 검증되지 않는다
