# §measurement-layer-blindness — 층을 안 세고 낸 등급은 **두 번 틀렸다**

- **Status:** 규칙 등재 (2026-08-14) · **실측 전 절차로 승격**
- **승격 경위:** §tenant-isolation-placeholder 실측에서 **연속 2회 등급 오류**.
  둘 다 원인이 같다 — 요청이 통과하는 층을 다 세지 않고 한 층만 보고 판정했다.

---

## 0. 규칙

> **격리·권한 실측은 요청이 통과하는 모든 층을 열거한 뒤 설계한다.**
> 층 목록을 명시하지 않은 실측은 착수하지 않는다.

### 층 목록 (이 repo, 2026-08-14 기준)

```
1. middleware.ts        matcher `/api/:path*` · `/api/admin/*` 는 User.role==='ADMIN' deny-by-default
2. enforceAction        조직 게이트 — (a)≡(b) 항등이라 거절 불가 (§tenant-isolation-placeholder)
3. 역할 게이트           ACTION_ROLE_MINIMUM — 조직 비교보다 **먼저** 반환한다
4. 라우트 자체 검사       organizationMember 조회 / userId 비교 / scopeKey·guestKey
5. 드리프트 500          §drift-masks-isolation — 차단이 아니라 판정 유예
```

## 1. 실제로 틀린 기록 (숨기지 않는다)

| 회차 | 오독 | 결과 |
|---|---|---|
| 1차 | 역할 게이트(3층) 조기 반환을 **"경로 미도달"** 로 읽음 | 조직 비교가 실행됐는지 판정 불가 상태에서 진행할 뻔함 |
| 2차 | 미들웨어(1층) 커버를 **"무방비"** 로 읽음 | 유출면을 11건으로 보고 → 실제 고객 도달 3건 |

2차가 더 무겁다. **미들웨어라는 실질 방어층의 존재 자체를 실측 설계에서 누락**했고,
그래서 라우트 레벨만 본 정적 분류가 런타임과 **5건 어긋났다**.

## 1.5 검증 도구 자신도 대상이다

> **검증 도구는 자기 자신을 대상에 포함시켜 1회 검증하기 전까지 결과를 채택하지 않는다.**

A4 단언은 작성 직후 `quotes/[id]/status` 를 "검사 없음"으로 분류했다 — 방금 넣은
검사를 못 읽은 것이다. 원인은 분석기 버그였다: `): Promise<{ ok: true } | ...> {` 의
**반환 타입 주석을 함수 본문으로 오인**해 헬퍼 본문이 `{ ok: true }` 로 잘렸다.
자기검증 조항이 없었으면 이 단언은 **통과하면서 아무것도 읽지 않는 상태**로 커밋됐다.

⚠️ **이번 세션 2번째**다 — 앞선 것은 `| tail` 파이프가 종료코드를 가려 실패를 성공으로
읽은 건이었다. 둘 다 "도구가 조용히 거짓말한다" 형태다.

따라서 모든 커버리지·분류 단언은 다음을 포함한다:
1. **자기검증** — 방금 고친 대상이 "고쳐진 것으로" 분류되는가
2. **corrupt→RED** — 각 인식 경로마다 1건씩 (커버 인식 / 검사 인식)
3. **열거 하한** — 수집이 0건으로 죽으면 단언이 조용히 통과하므로 하한을 건다

### 실패 사례 — 이 규칙을 세운 **다음 배치에서 어겼다** (배치 2→3)

배치 2 에서 단언 파일에 넣은 정규식 `/s` 플래그 6개가 `tsc` TS1501 을 내고 있었다.
당시 검증은 `tsc` 출력을 **소스 파일 경로로만 grep** 했고 **검증 도구 자신(테스트 파일)은
보지 않았다.** 그래서 "tsc 수정 파일 에러 0" 보고가 부정확했다.

§1.5 를 세운 배치의 **바로 다음 배치**에서 같은 형태로 어긴 것이다 —
규칙을 적는 것과 적용 범위를 넓히는 것은 다른 일이다.

> **절차: `tsc` 확인 범위에 테스트 파일을 포함한다.**
> 단언·픽스처·프로브 등 검증 자산은 "부수 파일"이 아니라 **검증 대상**이다.
> 파일 경로로 grep 해 좁힐 때는 검증 자산 경로를 함께 넣는다.

## 1.6 **접촉을 판정으로 읽지 않는다** (3번째 동형 오류)

> **어떤 모델·값을 건드렸다는 사실은 그것으로 판정했다는 증거가 아니다.**

A4 단언의 `orgMember` 마커는 `organizationMember.(findFirst|findUnique|findMany|count)`
만 보고 "검사 있음"으로 판정했다. 그러나

```ts
db.organizationMember.findMany({ where: { organizationId: id } })  // 데이터 조회
db.organizationMember.findFirst({ where: { organizationId: id, userId } })  // 판정
```

둘은 같은 모델을 건드리지만 **앞의 것은 호출자를 판정하지 않는다.**
`organizations/[id]/members` GET 이 앞의 형태로 임의 조직 멤버 명부를 반환하고 있었고
단언은 그것을 **신뢰 高(A티어)** 로 분류했다. → 마커를 `userId` 동반
`findFirst`/`findUnique` 로 한정(배치 3-B).

### 이번 세션 동형 오류 3건

| 회차 | 형태 | 무엇을 무엇으로 읽었나 |
|---|---|---|
| 1차 | `\| tail` 파이프 | 파이프 성공을 **명령 성공**으로 |
| 2차 | 반환 타입 주석 `{ ok: true }` | 타입 주석을 **함수 본문**으로 |
| 3차 | `findMany` 마커 | 모델 **접촉**을 **판정**으로 |

셋 다 "형태가 비슷하니 같은 것으로 친다"이다. 정적 판정을 세울 때마다 물을 것:
**이 신호가 내가 주장하려는 사실과 같은 것인가, 비슷할 뿐인가.**

## 1.7 우선순위 가정도 실측 대상이다

A5 스윕은 "인라인 `organizationMember` 직접 확인은 신뢰도 높다"는 **지시문의 가정**에
따라 신뢰 低(B·D) 티어부터 쳤다. 그런데 **유출은 신뢰 高(A) 티어에서 나왔다.**

기록해 둔다 — 실측의 우선순위를 정한 가정 자체가 실측으로 깨진 사례다.
가정은 탐색 순서를 정할 수는 있어도 **커버리지를 줄이는 근거가 될 수 없다.**
A티어를 "신뢰 高라 나중"으로 미룬 판단이 유효했다면 이 유출은 아직 안 나왔다.

## 1.8 규모 숫자는 **보고 숫자 전반**에 적용된다

§6 상시 제약("규모 숫자는 실측 전에 말하지 않는다")은 총괄의 가정만이 아니라
**보고자가 내놓는 숫자 전부**에 걸린다.

실제 사례 — "쓰기 29건". 이 숫자는 취약 티어의 **고유 라우트 수**였는데
**쓰기 핸들러 수**처럼 보고됐고, **두 배치에 걸쳐 승인 판단의 전제**로 쓰였다.
실측 결과는 **131건**(테넌트 접촉 + 미들웨어 미커버 쓰기 핸들러)이다.

숫자가 4.5배 틀리면 그 위에서 내린 "종료가 가깝다"는 감각도 함께 틀린다.

### 커버리지 보고 형식 (고정)

> **커버리지는 분모를 명시한 분수로만 보고한다. "N건 완료"는 쓰지 않는다.**
> 제외분은 **분모에 남긴다** — 분모에서 빼면 커버리지가 부풀고,
> 그것이 다음 사람이 종료를 오판하는 경로다.

예: `쓰기 23/131 (제외 7 포함)` · `읽기 30/59` — 축이 다르면 분수도 분리한다.

## 2. 절차

1. 실측 설계서에 **층 목록을 먼저 적는다**
2. 각 층에 **관문별 로그**를 심는다 — 결과(차단/통과)만으로는 어느 층이 판정했는지 못 가른다
   (§tenant-isolation-placeholder §0 로그 규칙의 일반화)
3. 차단이 나오면 **어느 층이 막았는지 기록**한다. "403" 은 증거가 아니다
4. 정적 분류는 **가설**이다. 런타임 실측이 판정이다

## 3. 스윕·단언에 적용

- **A5 런타임 스윕**: 요청마다 차단 주체 4분류 필수 —
  `미들웨어 / 라우트 검사 / 드리프트 500 / 미도달`. 4분류 없는 스윕 결과는 **채택 불가**
- **A4 재발 방지 단언**: 미들웨어 커버 경로를 own 으로 인식하되
  **프리픽스 하드코딩 금지** — `middleware.ts` 의 matcher 와 role 조건을 읽어 커버 집합을
  도출한다. 하드코딩하면 matcher 가 바뀔 때 단언이 **조용히 거짓말한다**
- corrupt→RED 실증은 **미들웨어 커버 경로 1건 + 라우트 검사 경로 1건 각각**.
  한쪽만 하면 커버 인식 로직 자체가 검증되지 않는다
