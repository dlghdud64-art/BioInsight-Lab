# §auth-provider-scope — 인증 수단이 Google OAuth 단독이다

작성: 2026-08-12
상태: **활성 등재** (동결 목록 아님 — 호영님 2026-08-12). 설계 미착수.
발원: 워크벤치 왕복 검증 시도 중 로그인 수단 부재로 막힘

---

## 0. 실측

`src/auth.ts` 의 `providers` 배열:

```ts
providers: [
  ...(hasGoogleOAuth ? [ Google({ ... }) ] : []),
]
```

**Google OAuth 하나뿐이다.** `/auth/signin` 화면의 "이메일로 계속하기" 는
`"이메일 로그인은 곧 제공될 예정입니다."` 안내만 있고 동작하지 않는다.

미들웨어는 `/app/*` · `/dashboard/*` · `/admin/*` 을 비로그인 시
`/auth/signin` 으로 돌린다. 공개 `/search` 의 검색 버튼도 로그인으로 보낸다.
→ **로그인 없이는 담기 이전 단계도 진입 불가.**

## 1. 왜 활성 목록인가 — QA 문제이기 전에 온보딩 병목

호영님 판단(2026-08-12):

> 실험실 구매 담당자의 회사 계정이 Google Workspace 가 아니면 **가입 자체가 불가능**하다.
> 국내 연구기관·제약사는 상당수가 아니다.

"사용자 앞에 세우기" 의 **첫 장애물이 될 가능성이 높다.** 그래서 동결 목록이 아니라
활성 목록에 둔다.

## 2. 이번에 처리한 것 — dev 전용 로그인 (§auth-dev-login)

고객 온보딩 문제와는 **별개**다. 우리가 제품을 밟을 수단만 먼저 만들었다.

- `Credentials` provider(`id: "dev-login"`)를 조건부로 추가.
- 게이트: `!requiresDestructiveConfirmation()` — 즉 **운영 DB host 도 아니고
  NODE_ENV=production 도 아닐 때만**. 판정 규칙을 재구현하지 않고 재사용했다.
- `.env` 를 개발 DB 로 바꾸는 순간 자동으로 살아나고, 운영을 가리키면 배열에서 사라진다.
- soft-deleted 사용자는 이 경로로도 들어올 수 없다.
- sentinel `auth-dev-login-gate.test.ts` (D1~D4) + corrupt→RED(무조건 추가로 바꾸면 RED).

⚠️ **이것은 고객용 대안이 아니다.** 비밀번호를 검증하지 않으며 운영에는 존재하지 않는다.

## 3. 착수 시 검토 항목 (설계는 아직)

- 이메일 + 비밀번호(자체 계정) — 가장 넓은 커버리지, 비밀번호 관리 책임이 생긴다
- 이메일 매직링크 — 비밀번호 없음. 이미 벤더 회신에 토큰 링크 인프라가 있다(재사용 가능)
- Microsoft/Entra ID — 국내 제약사·연구기관 상당수가 M365 를 쓴다
- 기존 SSO 코드(`lib/auth/sso-config.ts`, `convertSSOConfigToProvider`)와의 관계 —
  이미 조직별 SSO 설정 코드가 존재한다. 무엇이 배선돼 있고 무엇이 미배선인지 먼저 실측.

**우선 실측 1건**: `sso-config` 가 실제로 동작하는 경로인지, 아니면 미배선인지.
이번 세션에서 반복된 클래스(선언은 있는데 동작하지 않음)일 수 있다.

## §dev-login-ui-gap — provider 는 있는데 **화면 진입점이 없다** (2026-08-12 실측)

왕복 검증 1단계에서 드러났다. `dev-login` provider 는 **실재한다** —
`/api/auth/providers` 가 `{"dev-login":{"name":"개발 로그인 (dev only)"}}` 를 돌려준다.

**그런데 로그인 화면에는 진입점이 없다:**
- "Google로 로그인" 버튼
- "또는 이메일로 계속하기" → **"이메일 로그인은 곧 제공될 예정입니다."**

즉 **화면만 보면 "dev-login 이 없다" 고 결론내게 된다.**
우리는 `/api/auth/callback/dev-login` 에 직접 POST 해서 우회했다.

⚠️ **"도달하는가" 의 또 다른 사례다** — 이번엔 코드가 아니라 **사람의 도달성**이다.
   기능은 등록돼 있는데 그 기능에 닿는 문이 없다.

**등재만 한다** (호영님). 운영에서는 provider 자체가 존재하지 않아야 정상이므로
(§auth-dev-login D1/D2) UI 를 만드는 것은 **개발 빌드 한정**이어야 하고,
그 분기를 새로 만드는 것은 별건이다.

📌 다음 사람에게: dev-login 을 쓰려면 화면이 아니라 **엔드포인트**로 들어간다.
