# QUEUE — 렌더 도달 0 census

- 개설: 2026-09-26 (호영님 판정 · §inventory-dead-tabs-removed 에서 파생)
- 상태: 대기 (순서 판정 전)

## 왜 큐가 생겼나

`inventory-content.tsx` 는 라이브 파일인데, 그 안에 `{false && (…)}` 블록이 3개(639줄) 있었고
소비자 0 인 지역 컴포넌트가 3개(481줄) 있었다. **센티넬 31건이 그 구역을 재면서 GREEN 이었다** —
도달성 가드는 「이 파일이 라이브 경로에 물려 있는가」 만 묻기 때문에 전부 통과한다.
그 GREEN 중 일부는 CLAUDE.md 조항 본문에 「라이브 승계 유지(vitest GREEN 실측)」 로 기록되기까지 했다.

그리고 렌더 0 이 **비용 0 은 아니었다** — 죽은 블록에 값을 대는 쿼리가 살아 있어서
화면을 열 때마다 품목당 `GET /api/inventory/[id]/restock-request` 가 나갔다.

## 이미 닫힌 축

| 축 | 도구 | 현재 |
|---|---|---|
| 항상 거짓인 렌더 가드 (`{false &&` · `{false ?` · `if (false)` · `{0 &&`) | `__tests__/meta/render-unreachable-block-ratchet.test.ts` (래칫 · 상한 0) | **0곳** |

→ 래칫이 상한 0 이므로 이 축의 「남은 위치 목록」 은 **비어 있다.** 늘어나면 래칫이 위치를 찍어 준다.

## 남은 축 (이 큐의 일)

### ① 소비자 0 인 지역 컴포넌트
같은 파일 안에 `function <PascalCase>(` 로 선언됐지만 어디서도 `<Name` 으로 렌더되지 않는 것.
이번 건의 `InventoryCard` · `TeamInventoryCard` · `InventoryForm` 형태다.

🛑 **수치를 먼저 적지 않는다.** 첫 계측 시도가 셸을 거치며 정규식이 손상돼 **272 라는 거짓 수**를 냈다
(`[\s/>]` 가 `[\\s/>]` 로 깨져 `<Skeleton ` 같은 정상 사용을 못 셌다).
→ 검출기는 **파일로 써서** 돌리고, 알려진 양성(`ui/skeleton.tsx :: Skeleton` 처럼 확실히 쓰이는 것)이
  「사용 중」 으로 나오는지 **카나리**로 먼저 확인한 뒤에 수를 낸다.

⚠️ 이 축에는 정당한 예외가 많다 — `Suspense` fallback, `dynamic()` 으로만 참조되는 것,
`page.tsx` 의 default export 래퍼, 타입 전용. 분류표 없이 수만 세면 오탐 더미가 된다.

### ② 주석으로 감싸 둔 JSX 블록
`{/* … 실제 JSX … */}` 형태. 되살릴 의도인지 잔재인지 구분이 필요하다.

### ③ 그 구역을 재고 있는 센티넬 역추적
①②에서 나온 구역의 행 범위를 뽑아, 그 범위를 앵커로 쓰는 센티넬을 찾는다.
2026-09-26 에는 그 역추적이 **삭제 후 RED 로 사후에** 드러났다. 앞으로는 지우기 전에 센다.
